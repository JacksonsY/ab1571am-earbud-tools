# 05 · 评审、脱敏与发布

适合：适配补丁准备进入 PR、仓库或发布包。发布动作只按填写的目标和授权执行。

```text
请审查当前适配变更，准备可公开的交付物。先读 AGENTS.md、docs/PUBLICATION_AND_LEGAL.md、相关适配说明和实际 diff。

审查范围：[分支/提交/工作区文件]
目标发布位置：[仓库与分支、PR 或版本；未知则只做本地准备]
已授权动作：[本地审查 / 建立 PR / 推送 / 创建版本及资产，逐项写清]
本地私有材料目录：[路径；用于比较和脱敏，不上传]
会话目录：work/[任务代号]/

依次执行：
1. 从用户症状追踪到实现，核对所有新 profile、入口和调用者。检查旧行为是否回归、未知固件是否拒绝、两耳是否分别验证、失败是否会停止后续写入。
2. 运行与变更相称的检查，区分源码/二进制、离线/真机/UI 证据。不要把未执行的步骤写进“已通过”，也不要为发布重放健康设备上的写入。
3. 检查实际暂存区、待推送提交历史和解压后的发布资产；比较已知私有标识时只输出是否命中，不把秘密打印进报告。排除真实序列号、设备 UUID/地址、密钥、个人路径、原始日志、厂商固件/APK和私人备份。
4. 若发布可执行文件，检查调试路径、嵌入字符串、架构、最低系统版本和校验和。只打包明确允许的文件；重新从发布包运行适用的离线检查。
5. 更新支持矩阵、来源、限制、恢复边界和发布说明。新增支持与已验证支持要区分；研究/自用和免责声明不能替代授权或保证免责。
6. 在用户指定范围内完成提交、PR、推送或发布；没有发布授权时，交付已经准备好的补丁、审查结论和拟发布清单，不擅自上传。使用已有认证，不打印凭据或擅自修改全局网络/安全配置。
7. 对已执行的外部动作读取远端状态，核对提交、文件清单、版本和资产哈希。已发布资产不静默替换，变更使用新版本。

完成标准：给出简洁的变更与验证摘要、未解决问题、实际交付地址或本地待发布位置。若发现已公开敏感内容，先停止进一步分发并说明影响；历史清理、凭据处理和外部变更按维护者的具体授权推进，不能只添加免责声明。
```
