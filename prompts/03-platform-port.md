# 03 · 平台与传输层移植

适合：希望在 Windows、Linux 或不同的连接方式中复用研究与工具。更换主机平台不等于更换或验证设备固件 profile。

```text
请把本仓库必要的耳机查询/受限控制能力适配到目标平台。先读 AGENTS.md、docs/TOOLS.md、docs/PROTOCOL.md 和现有传输实现。

目标系统及版本：[填写]
计划使用的接口：[BLE / RFCOMM / USB / 尚待核实]
目标设备及 profile 证据：[已有文件路径或未知]
首个需要完成的功能：[例如 SDK 查询与双耳只读状态]
硬件访问授权：[明确的定向查询范围或仅离线]
会话目录：work/[任务代号]/

依次执行：
1. 先确认系统实际支持的 API、权限、配对及连接要求，使用厂商/操作系统/库的原始文档；不要给平台或标准库虚构蓝牙接口。现有 macOS IOBluetooth/CoreBluetooth 代码不能原样当作跨平台实现。
2. 将最小传输边界与报文/设备 profile 区分开，复用请求构造、帧分片合并、长度校验、超时、响应匹配和失败语义。只有确有第二种实现需求时才提取共享结构。
3. 优先选现有依赖或平台能力；必须新增依赖时说明理由，限定版本并记录运行要求，不修改无关系统设置。
4. 实现明确目标选择、唯一匹配、断开清理和超时处理。只读能力先完成；上层的固件校验、原值检查、写前记录和读回保护不能在移植中消失。
5. 用合成分片、粘包、截断包、错误命令号、断连和超时回放检查协议行为；用可观察的假传输验证拒绝路径不会发出写命令。
6. 有真实平台和访问授权时再做最小定向只读查询；没有该环境时交付实现与可运行检查，明确未完成平台/真机验证，而不是模拟一个成功结果。

完成标准：首个指定功能可验证；列出依赖、系统权限、运行命令、成功/失败的输出约定，以及原平台回归结果。把已支持、仅离线测试和未知能力分开记录。新增硬件写入能力另按 prompts/04-controlled-validation.md 处理，不能因传输连通就宣布修复完成。
```
